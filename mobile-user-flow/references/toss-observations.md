# 토스 실측 범위와 재사용 근거

2026년 9월 Android 토스 5.276.0의 로그인 상태에서 확인한 화면 구조를 요약했다. 일부 대표 경로에 대한 관찰이며, 현재 버전이나 다른 이용 환경의 화면을 보장하지 않는다.

이 문서는 당시 동선 보고서를 개인정보 없이 요약한 참고 자료다. 원본 스크린샷, 계좌·연락처·주소, 실제 프로필 이름, 기기 식별자와 로컬 도구 경로는 포함하지 않는다.

## 확인한 경로와 멈춘 지점

화살표는 실제 확인한 진입 순서를 나타낸다. 같은 행의 분기는 따로 탐색한 경로이며, 처음부터 끝까지 한 번에 완료한 거래를 뜻하지 않는다.

| 영역 | 확인한 진입 및 화면 | 확인하지 않은 구간 |
|---|---|---|
| 전역 구조 | 홈 / 혜택 / 쇼핑 / 증권 / 전체 탭 진입 | 각 탭의 모든 하위 기능 |
| 홈 | 자산·소비 요약, 송금과 내역 진입점 | 모든 카드·상품의 상세 |
| 송금: 계좌 | 홈 송금 → ‘어디로 보낼까요?’ → 계좌번호 입력 → 은행 선택 시트. 최근·내 계좌·즐겨찾기와 카메라 진입점 관찰 | 실제 계좌 입력, 수취인 확인, 금액 입력, 인증, 완료와 실패 |
| 송금: 다른 방법 | 카카오톡 탭의 링크 송금 안내, 연락처 탭의 검색·직접 입력·연락처 목록, 해외 탭의 국가·통화 목록 | 링크 생성, 대상 선택 이후, 해외 송금 실행 |
| 소비 | 홈 월 소비 내역 → 월별 요약·필터·거래 목록 → 거래 상세 | 필터별 결과 전체, 수정 저장, 뒤로 가기 시 필터·위치 복원 |
| 혜택 | 포인트 잔액 → 포인트 화면, 출금·교환 진입점과 미션 목록 | 출금·교환·미션 완료 |
| 쇼핑 | 분류 → 하위 분류의 상품 목록 → 상품 상세 → 주문 옵션 시트. 상세 하단의 찜·장바구니·구매 행동 영역 | 결제 진입 이후, 구매 완료·취소·환불 |
| 쇼핑 복귀 | 화면 상단의 뒤로 버튼으로 상세 → 목록 → 분류 이동 확인 | 검색·필터·스크롤 위치 보존의 엄밀한 검증 |
| 증권 | 증권 진입 시 내부 메뉴가 뒤로 / 증권 / 관심 / 발견 / 피드로 전환. 관심의 빈 상태·찾아보기, 발견의 분류·필터, 피드의 콘텐츠와 프로필 생성 안내 | 매매·주문·인증·실행 결과, 게시·댓글 작성 경로 |
| 전체 | 상단 검색 진입점, 최근 이용, 금융·생활 분야의 서비스 분류 | 검색 결과, 대부분의 개별 서비스, 설정·고객센터 내부, 목록 최하단 전체 |

세부 관찰:

- 계좌 입력 화면에는 입력하면 은행을 찾아준다는 안내가 있었다. 실제 자동 감지 기능은 시험하지 않았다.
- 거래 상세에는 분류, 메모, 합계 포함 여부, 결제 수단·일시, 나눠 내기 진입점이 보였다. 값을 변경하지 않았다.
- 상품 상세에는 가격·후기·배송·판매자 정보와 하단 행동 영역이 있었다. 주문 옵션 시트까지 열렸지만 결제를 진행하지 않았다.
- 피드의 프로필 생성 안내는 관찰했으나 온보딩 전체를 검증한 권장 흐름으로 제시하지 않는다.

## 관찰에서 설계로 옮기는 방법

1. 사용자의 핵심 작업을 먼저 정한다. 토스의 기능 이름 대신 해당 업종의 대상·행동·완료 결과로 치환한다.
2. 위 경로에서 구조를 고른다. 예: 소비 요약 → 목록 → 상세를 운동 기록이나 업무 이력에 적용한다.
3. 분기 이유를 보존한다. 계좌/연락처처럼 입력 수단이 다를 때만 나누고, 새 앱에서는 검색/스캔/최근 대상으로 바꿀 수 있다.
4. 아직 관찰하지 않은 구간은 새 앱의 요구사항으로 설계한다. 인증·완료·재시도·중복 방지·입력 보존을 토스 실측으로 인용하지 않는다.
5. 산출물에 ‘관찰’, ‘해석’, ‘설계 제안’, ‘미확인’을 필요한 곳에 구분한다. 특정 패턴의 성능·전환 효과를 수치 없이 주장하지 않는다.

예: 시설 예약에 적용할 경우 ‘홈의 예정 예약 → 시설 검색/최근 시설 → 시설 상세 → 날짜·인원 선택 → 예약 확정 → 결과·예약 내역’으로 제안할 수 있다. 짧은 인원 선택은 시트에 두고, 일정 선택·변경 가능 여부는 업무 규칙에 맞춘다. 예약 확정 이후와 복귀 상태 보존은 이 예시를 위한 설계이며 관찰된 토스 경로가 아니다.

## 실제 앱을 추가 조사할 때만 적용

- 화면 전환 후 최신 화면과 요소를 확인하고 다음 행동을 정한다. 지연 로딩이나 팝업이 나타나면 이전 좌표·요소 참조를 재사용하지 않는다.
- 도구의 뒤로 가기 성공 응답만으로 이동을 단정하지 않는다. 목적 화면이 실제로 보이는지 확인한다.
- 진입 버튼과 실행 버튼을 구분한다. 탐색 중 가입·프로필 생성·주문처럼 계정 상태를 바꾸는 단계가 나타나면 기존 사용자 허가 범위를 확인한다.
- 예상하지 않은 변경이 발생하면 후속 변경을 멈추고 관찰 사실과 확인된 영향을 보고한다. 취소·삭제도 영향 범위를 확인한 뒤 사용자 지시에 따라 수행한다.

이 조사 수칙은 실제 앱을 조작할 때의 기준이다. 이 스킬로 동선을 기획하거나 코드를 구현하는 데 휴대폰 연결이나 추가 승인이 필요하다는 뜻은 아니다.
