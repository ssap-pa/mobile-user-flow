# 관찰에서 업종별 설계로 옮기기

출처: 2026년 9월 Android 토스 5.276.0의 로그인된 사용자 화면 일부를 직접 탐색한 기록. 주요 탭과 대표 하위 경로를 확인했으며 앱 전체와 송금·결제·투자 실행 완료는 검증하지 않았다. 아래 ‘관찰’만 실측이고 적용 규칙과 업종 예시는 설계 제안이다. 원본 화면의 개인정보는 포함하지 않는다.

단계별 관찰 경계는 [토스 실측 범위](toss-observations.md)를 참고한다. 아래 표의 ‘추출한 패턴’에는 관찰에 대한 해석이 포함되며, 전환율이나 사용성 개선이 측정된 것은 아니다.

| 관찰한 구조 | 추출한 패턴 | 사용할 조건 | 다른 분야에 적용 |
|---|---|---|---|
| 홈의 자산·소비 요약과 송금 진입 | 현재 상태와 즉시 행동을 가까이 배치 | 반복 방문 시 상태 확인 후 행동하는 서비스 | 학습: 진도와 이어 학습 / 현장 업무: 오늘 배정과 작업 시작 |
| 송금의 계좌·연락처 등 방법 분기, 최근 대상 | 사용자에게 익숙한 시작 방법과 반복 단축 | 같은 목적에 여러 입력 수단이 존재 | 예약: 최근 장소/검색 / 재고: 상품 검색/바코드 |
| 계좌 입력 중 은행 선택 화면 | 주 작업의 맥락 안에서 속성 선택 | 선택이 짧고 현재 입력에 종속 | 예약 인원 선택 / 업무 우선순위 선택 |
| 소비 요약 → 필터 목록 → 거래 상세 | 개괄부터 개별 항목으로 정보 깊이 증가 | 항목이 누적되고 찾기·비교가 필요 | 운동 기록 → 기간별 목록 → 세션 상세 |
| 쇼핑 분류 → 목록 → 상세 → 주문 옵션 | 탐색과 실행 준비를 구분 | 대상을 이해·비교한 후 실행 | 강좌 탐색 → 강좌 상세 → 수강 일정 선택 |
| 상품 상세 하단 행동 영역 | 긴 콘텐츠에서도 실행 위치 유지 | 상세를 읽은 후 행동하며 본문이 김 | 시설 상세의 예약 버튼 |
| 증권 영역의 내부 메뉴 | 복잡한 독립 영역의 내부 구조 | 영역 안에 반복 방문할 목적이 여러 개 | 관리자 영역의 작업/통계; 작은 앱에는 생략 |
| 관심 화면의 빈 상태와 찾기 진입 | 빈 화면에서 첫 행동 연결 | 처음 이용하거나 조건에 맞는 항목 없음 | 저장한 레시피 없음 → 레시피 찾기 |
| 피드 접근 시 프로필 생성 안내 | 기능 필요 시점의 온보딩 | 해당 기능이 프로필을 실제로 요구 | 댓글 작성 시 작성자 설정; 읽기까지 일괄 강제하지 않기 |
| 전체 메뉴의 서비스 분류 | 주 내비게이션 밖의 기능 발견 | 서비스 수가 많고 이용 빈도가 분산 | 병원 서비스 목록 / 기업 업무 도구 목록 |
| 포인트·미션 영역 | 재방문 목적의 별도 진입 | 보상이 핵심 가치와 관련되고 운영 가능 | 학습 목표 확인; 필요 없으면 보상 기능 생략 |

## 도메인별 선택 예

### 예약

장소/서비스 탐색 → 상세 → 가능한 일정 → 필요한 예약 정보 → 예약 확정 → 결과/변경 경로. 홈에 예정된 예약을 둔다. 일정 조회만으로 예약을 확정하지 않는다. 만석·시간 변경·확정 실패 상태를 설계한다.

### 교육

진도/이어 학습 → 수업 → 학습 활동 → 결과 → 다음 수업. 단순 콘텐츠 열람에는 확인 화면을 넣지 않는다. 다운로드가 있으면 저장 상태와 오프라인 접근을, 진도 저장이 지연되면 재진입 시 복구를 정의한다.

### 현장 업무

오늘 작업 → 작업 상세 → 체크리스트/증빙 → 제출 → 접수 또는 완료. 기존 탭이 있으면 유지하며, 통신이 불안정한 환경에서는 임시 저장 → 동기화 대기 → 서버 접수 상태를 구분한다. 제출 실패 시 증빙을 잃지 않게 한다.

### 커뮤니티

관심 주제 → 게시글 목록 → 상세 → 저장/작성. 프로필이 필요한 행동에서만 설정을 연결한다. 작성 중 이탈·임시 저장·게시 실패·게시 완료를 구분한다. 결제나 쇼핑 기능은 추가하지 않는다.

## 가져오지 말아야 할 결론

- 탭이 다섯 개여야 한다거나 모든 앱에 ‘혜택/쇼핑/전체’가 필요하다는 결론.
- 송금 인증·결제 완료처럼 탐색하지 않은 구간을 토스의 확인된 동선이라고 설명하기.
- 뒤로 가기 상태 복원, 오류 회복 등 새 설계 기준을 실측 결과로 설명하기.
- 프로필 생성이나 보상 기능이 전환율을 높인다고 근거 없이 단정하기.
